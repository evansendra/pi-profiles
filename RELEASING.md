# Releases

Releases are manual. Pushing a tag never publishes by itself.

1. Review the diff, source, Git metadata/history, and npm payload for private data. Use a public-safe Git author identity. Do not rewrite existing history as part of a release.
2. Choose an unused patch/minor/major version, update `package.json` and `CHANGELOG.md`, then run `npm test` and `npm run prepublishOnly`.
3. Run `npm pack --ignore-scripts --pack-destination <temporary-directory>`. Inspect every archive entry and its contents; record the tarball's SHA-256. No generated archives or private audit notes belong in Git.
4. Commit the reviewed files and create an annotated `vVERSION` tag at that exact commit. Push only the intended branch and tag.
5. Configure npm trusted publishing for this public repository and `publish.yml`, with no environment name, allowing direct publishing. Do not add an npm token to GitHub.
6. Run the **Publish to npm** workflow manually against the version tag, supplying `tarball_sha256` from the reviewed tarball. The workflow tests, rebuilds, checks the exact payload hash, and publishes with GitHub Actions provenance.
7. Verify the workflow succeeded, npm's version, latest tag, integrity, downloadable tarball, and provenance attestation. Create the GitHub release for the verified tag with reviewed changelog notes.
8. If a step fails, check remote/npm state before retrying. Never move a published tag or reuse a published version for changed content.

The workflow requires Node 24/npm with trusted-publishing support and a GitHub-hosted runner. Provenance is generated by npm/GitHub, not a README image.
